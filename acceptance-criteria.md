# Acceptance Criteria
<!--
Acceptance criteria tell you when a user story is DONE. Each one must be testable: pass or fail.
Write 2–3 criteria for every user story using this format:

Given [a situation], when [the user does something], then [this should happen].

Tips:
- Number them under their story: AC1.1 and AC1.2 belong to US1.
- Describe what the user SEES, not how the code works.
- Include at least one "what if it goes wrong" case per story (empty input, no results).
- Avoid vague words like "fast," "nice," or "easy." Could a classmate test it and agree it passed?

Example:
## US1: View today's menu
- AC1.1: Given I open the App page, when it loads, then I see each dish with its name, photo and price.
- AC1.2: Given no dishes are added yet, when I open the menu, then I see "No dishes today yet."

AC - Acceptance Criteria
-->

### Feature: Outfit Builder
US1: As a User, I want to mix and match different clothing pieces, so that I can create personalized, coordinated outfits for specific occasions
- AC1.1 Users can select and combine items across multiple categories (tops, bottoms, outerwear, and accessories).
- AC1.2:Users can add, swap, or remove individual items without clearing the rest of the outfit.

### Feature: Outfit Gallery & Style Filters
US2: As a User, I want to view organized outfit collections and filter items by category and style, so that I can locate outfits that match my selected preferences.
- AC2.1: The lookbook displays organized outfit collections with product images and layouts.
- AC2.2: Users can filter items by category, style, color, and occasion.

### Feature: Product Details with Size Guide 
US3: As a User, I want to view item details, check size options, and verify stock availability, so that I can select the correct clothing items.
- AC3.1: Product pages display the item name, price, description, images, and an interactive size guide.
- AC3.2: Users can select an available size, while out-of-stock sizes or items are disabled from selection.
